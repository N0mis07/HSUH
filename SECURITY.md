# Security

## Scope and threat boundary

HSUH is a **single-owner VPS client**, not a multi-tenant service. It runs with the VPS user's permissions; never expose it with arbitrary agent tools enabled. The initial integration permits only Hermes `clarify`. Existing native Hermes sessions, delegated jobs and credential vaults are not bridged.

- Default bind: `127.0.0.1`, exact loopback Host allowlist, same-origin mutations, custom request header, process-local HttpOnly/SameSite session cookie.
- Public mode: exact HTTPS origin; Cloudflare Access RS256 JWT validation with pinned team issuer, application audience, expiry/issued-at and signed owner email. Every path is protected. Edge Access must also restrict the owner. Never trust an email header alone or publish loopback mode behind an anonymous proxy.
- ZeroFrame alternative: explicit `HSUH_AUTH_MODE=zeroframe`, exact HTTPS issuer and public origin, and pinned `HSUH_SSO_OWNER_ID`. ES256 signature, exact single audience, issuer, subject, role, issued-at and expiry (maximum one hour) are required on every protected request. Only that owner's pass works, even if other issuer users have site permissions. The callback accepts only bounded form POSTs from the configured issuer, checks the Secure/HttpOnly host-only state cookie and signed nonce, then consumes the server-side ten-minute challenge once. API mutations retain their exact-origin/header checks. Public-key fetches have a timeout, bounded response and cache/miss throttling; an unavailable issuer fails closed when no current key is cached. Host-only pass cookies are never shared with sibling hosts. Origin authentication must be verified before replacing any legacy edge gate.
- No query-string authentication, access logs, browser token storage, client chat persistence, offline caching or public telemetry. The owner-only activity adapter reads a fixed projection of native session metadata and titles through read-only SQLite connections, closes them promptly, caches results and bounds query time. It does not read message bodies, system prompts, credentials or process arguments/environments. Provider stdout/stderr and arbitrary exceptions are not browser output.
- OpenUI replies use a locally bundled MIT-licensed renderer and a six-component library with no raw-HTML, URL, remote tool or mutation components. Bounded programs must parse against that library; unsupported/tool-bearing programs display as text. React escapes text props. Checklist state stays in the current view and cannot issue agent commands. No OpenUI cloud transport or observability sink is installed. The original instruction that model text cannot execute arbitrary HTML/JavaScript remains in force.
- Application state is memory-only and bounded. Worker processes are isolated per turn, limited to two concurrent workers, time-bounded and stopped as a process group. This is **not an OS sandbox**.
- Website credential entry is disabled. Chat and clarification answers are model-visible; do not enter secrets. A user who pastes a secret in ordinary chat would be sending it to the configured model. HSUH does not claim to identify every possible secret.
- Native Hermes may maintain its own operational/authentication files. HSUH disables trajectories, memory, context-file injection and background review for its workers, passes no session database, and does not modify saved provider/profile settings. Standard library/OS process memory is not a secret vault.
- Native provider-error request dumps are a separate retention path: disabling trajectories does **not** disable them, and native secret-pattern redaction does **not** remove ordinary conversation text. Before starting a conversation, HSUH redirects the source-verified native `agent.logs_dir` to a fresh parent-owned mode-0700 temporary directory. Native redaction remains enabled. The parent removes that directory after reaping the worker on success, failure, timeout or cancellation, including forced termination. This is a version-sensitive native attribute, not a documented no-retention constructor option; incompatible runtimes must fail closed and require fresh source review.
- Diagnostic isolation is **not** an absolute memory-only confidentiality guarantee: transient redacted request bodies can exist in that private temporary directory while a turn runs. An unclean parent/VPS crash can leave it behind; the operator must secure the temporary filesystem and remove stale `hsuh-diagnostics-*` directories only when no owning HSUH process is running. HSUH does not sweep or delete native profile files. Backups, swap, provider retention and other native operational writes remain outside chat deletion.

## Reporting

Do not publish credentials, personal histories, raw authentication headers or exploit details in a public issue/PR. Use GitHub's private vulnerability reporting if enabled on the repository; otherwise open a minimal issue requesting a private contact channel without sensitive details. Maintainers should enable private vulnerability reporting before inviting reports.

The project is an early version, not an audited production platform. Separate code tests, independent source review, edge-configuration checks, authenticated hosted acceptance and actual-device PWA installation. An empty quota response is not an unlimited budget; a failed worker is not a successful assistant response.
